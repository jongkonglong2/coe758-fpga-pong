# coe758-fpga-pong
FPGA-based two-player Pong video game processor in VHDL for the Xilinx Spartan-3E (640x480 @ 60 Hz VGA)
## System Overview

This project implements a two-player Pong game (Simple Video Game Processor) in VHDL on the Xilinx Spartan-3E FPGA (`xc3s500e-5fg320`). It drives a 640x480 @ 60 Hz VGA display through a 24-bit RGB video DAC (`Rout<7:0>`, `Gout<7:0>`, `Bout<7:0>`, pixel clock `clk_25` on pin `A4`, horizontal sync `h_sync` on `C5`, and vertical sync `v_sync` on `D5`) and accepts player input from four on-board slide switches (`H18` for `left_up`, `N17` for `left_down`, `L13` for `right_up`, and `L14` for `right_down`).

## Module-by-Module Breakdown

- **`constants.vhd`**: Defines the VGA timing parameters—horizontal (`640` active, `16` front porch, `96` sync pulse, `48` back porch = `800` total) and vertical (`480` active, `10` front porch, `2` sync pulse, `33` back porch = `525` total)—along with court wall boundaries (`wall_inset = 21`, playable court `x = 30..611`, `y = 30..451`, goal gates `y = 151..350`), paddle geometry (`15x100` px, `paddle_step = 2` px/frame), and ball geometry (`10x10` px, `ball_step = 2` px/frame).
- **`clock_divider_2.vhd`**: Divides the 50 MHz system clock (`clk_50`) by 2 using a toggling flip-flop (`clk_25_s`) to generate the 25 MHz VGA pixel clock (`clk_25`).
- **`count_gen.vhd`**: Counts horizontal pixels (`0..799`) and vertical lines (`0..524`) on each rising edge of `clk_25`, emitting a single-cycle `new_frame` strobe at `(799, 524)` to pace game logic at 60 Hz.
- **`sync_gen.vhd`**: Generates registered active-low `h_sync` (`656 <= h_count < 752`) and `v_sync` (`490 <= v_count < 492`) signals on the same clock edge as the registered RGB output.
- **`paddle.vhd`**: Synchronizes the four slide switches through a 2-stage `ASYNC_REG` flip-flop chain (`switches_meta`, `switches_sync`), debounces them over two consecutive frames (`controls = previous`), updates `left_y` and `right_y` by `±2` px/frame within `[30, 349]`, and outputs active pixel masks `left_paddle` and `right_paddle`.
- **`ball.vhd`**: Updates ball position and velocity on `ball_new_frame_s` (delayed by 1 clock cycle after `new_frame` in `top_level.vhd` so paddles update before collision checks). Reflects off paddle front/back faces and top/bottom ends (`bounce_off_end`), includes a pinch guard when a moving paddle traps the ball against a top/bottom wall, bounces off top/bottom/side walls, enters `exiting` mode (`goal_ball = '1'`) when passing through a goal (`151 <= y` and `y + 10 <= 350`) until completely offscreen (`x = -10` or `x = 640`), and respawns at the center (`x = 315, y = 235`).
- **`VGA.vhd`**: Implements a priority RGB multiplexer (`blanking -> red goal ball #FF5260 -> cream ball #FFF6E2 -> cyan left paddle #42D9F2 -> amber right paddle #FFC46B -> 7-segment score digits -> slate walls #839AB6 -> dashed center line #40536D -> navy court #121D30 -> dark margin #090F1C`) and a 7-segment scoreboard (`draw_digit`, `20x36` px digits at `x = 280..299` and `340..359`, `y = 45..80`) that increments once per goal using `goal_seen_in_frame` and `goal_scored_locked` and resets to `0-0` after reaching `9`.
- **`top_level.vhd` & `mapping.ucf`**: Integrates all modules, wires ChipScope `ICON` and `ILA` debug probes (`ila_data`, `trig0`), and constrains all Spartan-3E FPGA pins and 50 MHz (`TS_board_clock`) / 25 MHz (`TS_pixel_clock`) clock domains.
